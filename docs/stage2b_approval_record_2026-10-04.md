## A2. 修订协议的**逐条替换表**（D-1/D-8 的规范性内容：被替换的旧条款逐条列出）

| 旧条款（`design_freeze_g4_specdec.md` v0.3，DRAFT、批准栏未勾选） | 旧条款内容 | 本次处置 | 理由 |
| --- | --- | --- | --- |
| **`:16`** | 判定 = `SpecDec ids == target-only greedy ids`（exact equality；**指生产 SpecDec 路径**） | **被替换**：Gate A 判据改为"**serial oracle（`M=1`，与 AR 同路径）**逐 token 与 AR 相等" | 生产（`M=4` 块验证）与 AR 的差异已被实测为**数值行为**（F13 prod 首分歧 47），按原判据无法成立 |
| **`:83`**（instrument/对象部分） | **B6** correctness gate：判据 `exact ids equality`（对生产路径） | **被替换**（同 `:16`）：门的**仪器与对象**改为 serial oracle | 同上 |
| **`:83`**（其余部分） | prompts 覆盖清单（自然语言/数学/代码/短/长/全接受/首位拒绝/中途拒绝/EOS/非 4 倍数）；条件 `base_bf16` **与** `v_fp8`；全 finite；多次确定性一致；**未过门禁止 acceptance 测量/pilot/final** | **保留**（逐条继续有效）；但**必须同时承认两点**：① 这份 prompts 覆盖清单**未**被 Stage 2b 覆盖（Stage 2b 只跑 4 个 8K **自然语言** family）；② 历史覆盖（`g4_b6_correctness.py` 的 10 类 case × 2 KV 档）是**旧口径（production `M=4`）**证据 ⇒ **不能**算作新口径覆盖。详见 §A4（**六个状态**互不推出）与 §A5（B6 类型覆盖轮待办） | 与 KV 分层设计无关；每 KV 条件各自验证是 D-6 |
| **`:96`** | "**B6 exact-token-id 门不可取消**"（因 BF16 cache 漂移风险） | **保留约束力，但适用对象改为 serial oracle 门**；**生产层不再受该门约束** | 该条的风险理由（cache 数值漂移翻 token）针对的是"生产路径是否与 AR 逐 token 相同"，现已改为"如实报告" |
| **`:83` 放行范围**（"B6 未过禁止 acceptance 测量/pilot/final"） | 旧文**未写明**是"每 KV 条件分别放行"还是"BF16 与 v_fp8 全部通过后全局放行" | **新增澄清条（需小组显式选定读法，见 §A5-2）**：推荐**按 KV 条件分别放行**（`base_bf16` 过 ⇒ 放行 BF16 侧；`v_fp8` 过 ⇒ 放行 FP8 侧） | 旧文把门定义为"**条件** `base_bf16` 与 `v_fp8`" ⇒ 分别放行是**对旧条款的解释（clarification）**，不改变判据数值；但两种读法后果不同，必须在纪要中显式选择，**不得默认**。硬规则：**BF16 通过绝不外推为 FP8 通过** |
| **（新增，必须写入协议）** | — | **production exact-id 门被移除**；production 与 AR 的任何 token 分歧**必须如实报告**：首分歧位置（输出内下标 + 绝对位置）、共同前缀 `P`、两侧 token、两侧完整输出与实际长度、两侧 work 统计、并列分类（当前一律 **TIE-C**）；**禁止**"同输出无损加速 / 输出等价 / lossless" 表述 | `production_correctness_decision:60` 的声明边界；`g5_measurement_protocol:159-164` 的 speedup 资格 10 条不含 `ar_equal` |
| **（新增，必须写入协议）** | — | **申报边界**：serial oracle 通过 ⇒ **只**说明"控制逻辑在与 AR 同路径时与 AR 逐 token 相等"，**不等于** production（`M=4`）与 AR 输出一致；速度比一律标注"**分歧轨迹上的比较**"并同时报告 `P` 与两侧接受统计/轮数 | 同上（防止把分层结果读成"同输出无损加速"） |

> **⚠️ 一句话说清性质**：这不是"门没有取消"，而是**serial 门保留、production 门被移除** ——
> 即**替换了旧文件里针对生产路径的 exact-id 判据**，属**实质协议变更**，必须由小组按上表逐条确认。

## A5. 两处覆盖范围问题的**推荐处置**（均需小组选定）

### A5-1（对应 D-11）`:83` 的 prompts 类型覆盖：**不修改、不取消，另列待办**

* **现状（事实）**：旧口径下确有历史覆盖 —— `specdec/engine/g4_b6_correctness.py` 定义 10 类 case
  （`natural-1`/`natural-2`/`math`/`code`/`short`/`long`/`len13`(非 4 倍数)/`len5`/`len2`(预算 < k)/`eos-prone`），
  历史结果 `B6-fp32` PASS 20/20、`B6-bf16` CHECK 19/20 —— 但**那是旧口径（production `M=4`）**证据。
* **缺口（必须写明）**：**新口径（serial oracle exact-id）下这 10 类 case 完全没有覆盖**；
  Stage 2b 的 4 个 8K 自然语言 family **只映射到"自然语言 + 长上下文"两项**，
  且 `rounds` 里虽自然出现全接受/拒绝轮，但那是**观测**、不是为这些类型**设计**的用例。
* **推荐（选项 a）**：**保持 `:83` 覆盖要求不变**，把 **B6 类型覆盖轮**列为**独立待办**：
  ① **工具改动**：现有 serial-oracle 运行器是 **manifest/family 取数**，跑任意 prompt 需要"prompt 来源模式"（属工具改动，需批准 + CPU 自测）；
  ② **成本估算（估算，非承诺）**：10 类 case × 3 模式 × 2 次 = **≥60 runs**（BF16）+ ≤10 次诊断；短 prompt 单次开销小，但计数仍按 run 计；
  ③ **准入条件**：D-1…D-4 已批准、工具改动完成并自测通过、`preflight` 返回 0、环境门通过。
* **选项 b（修改/豁免该要求）**：属**实质协议变更**（放宽 `:83` 的覆盖要求）⇒ 必须**单独列出并批准**，写明放宽范围与理由；**不得**在文字里隐去。
* **选项 c（暂缓决定）**：则"完整 B6"状态一律标**"未完成"**，且 **②/③/④ 不得被声称**。

### A5-2（对应 D-12）"B6 未过禁止 acceptance 测量/pilot/final" 的**作用范围**

* **选项 a（推荐：按 KV 条件分别放行）**：`base_bf16` 过 ⇒ 放行 BF16 侧；`v_fp8` 过 ⇒ 放行 FP8 侧。
  **性质 = 对 `:83` 的解释（clarification）**，不是修改（旧文把门定义为"**条件** `base_bf16` 与 `v_fp8`"）。
  **后果**：进度不被另一个 KV 条件阻塞；但**必须**在每条结论上标明 KV 条件，并遵守"**BF16 通过绝不外推为 FP8 通过**"。
* **选项 b（全局放行）**：`base_bf16` **与** `v_fp8` 全部通过后才允许任何 acceptance 测量/pilot/final。
  **后果**：BF16 侧的结果在 FP8 门通过前**不能用于任何下游用途**（等于把 BF16 Stage 2b 的结果先"封存"）；
  排期上 FP8 成为 BF16 的前置。**风险最低、进度最慢。**
* **无论选哪种**：报告里必须区分 §A4 的**六个状态**（`STAGE2B_PASS` / `B6_BF16_PASS` / `B6_VFP8_PASS` / `FULL_B6_PASS` / `BF16_FORMAL_READY` / `FP8_FORMAL_READY`）——"`STAGE2B_PASS`"**不等于**"`B6_BF16_PASS`"，更**不等于**任何 `*_FORMAL_READY`。
