# 位置 8209：QKᵀ 的 **2×2 执行形状分解** —— 持续分歧来自 **M**，且与 N **双向交互**（2026-10-02）

> **本轮唯一目标**：固定真实捕获的 Q/K **数值**，只改 `torch.matmul(q, k_rep.transpose(-2,-1))` 的
> **整体执行形状**（M = query 行数 ∈ {1,4}，N = 可见 key 数 ∈ {8209,8212}），
> 用六格 A..F 判定"位置 8209 第 0 行的持续分歧"来自 **M**、**N**、还是**二者的交互**；
> **raw 与 scaled 分别记录**。

## 0. 结论（一句话 + 关键数字）

**归因 = `M`（query 行数 1→4）**，并且 **M 与 N 之间存在交互（双向）**；**N 单独不足以复现**观测到的差异。

观测对象是"真实 S(1,8209) 与真实 B(4,8212) 的第 0 行差异"（= `A_vs_D`，因为 A ≡ 真实 S、D ≡ 真实 B **逐位**）：
**3 个坐标**不同、`max|Δ| = 64`（raw）/ `4`（scaled），坐标为 `(head0,key2367)`、`(head1,key4981)`、`(head9,key4011)`。

| 事实 | 数值（raw | scaled） | 含义 |
| --- | --- | --- |
| **A→C（只改 M，N 固定 8209）** | 3 个坐标 / max 64 | 3 / max 4 | 与 `A_vs_D` **坐标集合、个数、幅值完全相同** ⇒ **M 单独就能完整复现观测差异** |
| **A→B（只改 N，M 固定 1）** | 2 个坐标 / max 8 | 2 / max 1 | N 在 M=1 下**有效**，但坐标集合不同（仅 `(9,4011)` 与 M 效应重叠） |
| **C→D（只改 N，M 固定 4）** | **0**（逐位相同） | **0** | N 在 M=4 下效应为 **0** |
| **E→F（只改 N，M=4，内容恒为 q1）** | **0**（逐位相同） | **0** | 把内容完全固定后仍为 0 ⇒ 上面那条不是内容造成的 |
| **C→E / D→F（内容控制）** | **0**（逐位相同） | **0** | 第 0 行不受其余 query 行内容影响 |

* **M 效应**（`A≠C` 且 `B≠D`）：**成立**（两个 N 下都成立，各 3 个坐标、`max|Δ|=64` raw）。
* **N 效应**（`A≠B` 且 `C≠D`）：**按定义不成立**（M=1 下成立、M=4 下为 0）。
* **交互**：**成立**（`interaction=True`）；而且是**双向**的 —— 不只"N 的敏感性依赖 M"，
  连"M 改动哪些坐标"也依赖 N（第三个坐标在 N=8209 下是 `(9,4011)`，在 N=8212 下是 `(4,4453)`）。
* **边界层次**：`raw`（除法**之前**的 matmul 输出）**已经**不同 ⇒ 边界在 **`matmul` 本身**，
  **不是**随后的 `raw / √head_dim` 这一步（见 §5 的口径说明）。
* **设备依赖（如实记录）**：同一个 2×2 在**首跑**里因为我的缺陷落在 **CPU** 上执行，
  那次**六个 M/N 比较全部逐位相同**（即 CPU 后端下 M/N 改变对第 0 行"零效应"）
  ⇒ 该敏感性是 **CUDA 执行路径**的性质（**支持性推断**；未做 profiler，**不**声称是哪个 kernel/tile）。

## 2. 设计：六格与"为什么是这六格"

| 格 | M（query 行） | N（可见 key） | q 来源 | k 来源 | 作用 |
| --- | --- | --- | --- | --- | --- |
| **A** | 1 | 8209 | `q1 = q_rope[0,:,0:1,:]` | `k8209 = k_visible` | **复现真实 S**（门） |
| **B** | 1 | 8212 | `q1` | `k8212 = 真实 B 的 k_visible` | M=1 下的 N 效应 |
| **C** | 4 | 8209 | `q4_real = q_rope`（真实 B 的 4 行） | `k8209` | N=8209 下的 M 效应 |
| **D** | 4 | 8212 | `q4_real` | `k8212` | **复现真实 B**（门） |
| **E** | 4 | 8209 | `q4_repeat = q1.repeat(1,1,4,1)` | `k8209` | 内容控制（第 0 行必须与 C 逐位相同） |
| **F** | 4 | 8212 | `q4_repeat` | `k8212` | 内容控制（第 0 行必须与 D 逐位相同） |

* **统一比较区**：恒为 `output[0, :, row0, 0:8209]`，形状 `(12, 8209)` —— batch0、12 个 query head、
  第 0 行（B 路径的**决策行**）、**共同可见**的 key 前缀（0..8208）。长度不同的 3 个 key（8209..8211）
  **不参与**比较（B 的 post-mask scores 里有 36 个 `-inf`，是设计使然）。
* **GQA**：`k_rep = M.kv_repeat(k, 12//2)` = **生产同一函数**（第 h 个 query head ↔ 第 h//6 个 KV head），
  控制 4 校验 `equals_production_kv_repeat=True`。
* **只改形状、不改公式**：六格用的是**同一条**表达式 `torch.matmul(q, k_rep.transpose(-2,-1))`，
  随后 `raw / (head_dim ** 0.5)`；`dtype` 恒为 bf16；`allow_tf32=False`。
* **为什么必须 live 捕获而不是从 `.pt` 里取**：上一轮 `.pt` 只保存了 `q_rope`/`k_visible` **当次**张量，
  要在**同一次进程、同一精度状态**下做六格比较（否则又引入跨 run 变量）；而"实时捕获是否与上一轮逐位一致"
  由 `vs_previous_l0ops_pt`（q/k/真实 scores 全部 `exact_equal=True`）单独证明。

## 5. 逐坐标数值（最有信息量的一张表；raw 口径，bf16 原样）

| 坐标 (head, key) | A (M1,N8209) | B (M1,N8212) | C (M4,N8209) | D (M4,N8212) | E | F | 谁改变它 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `(0, 2367)` | 3936 | 3936 | **3952** | 3952 | 3952 | 3952 | **只有 M** |
| `(1, 4981)` | 9536 | 9536 | **9600** | 9600 | 9600 | 9600 | **只有 M** |
| `(4, 4453)` | 1888 | **1880** | 1888 | 1888 | 1888 | 1888 | **只有 N**（且只在 M=1） |
| `(9, 4011)` | **207** | **208** | 208 | 208 | 208 | 208 | **M 与 N 都能改到同一个值** |

三条可核的观察：
1. **M=4 的值在四个格里完全一致**（C=D=E=F）：M=4 的执行对"多 3 个 key"和"其余行内容"**都不敏感**；
2. `(4,4453)` 是**只有 N 能改**的坐标，而它在 M=4 下**不动** ⇒ N 的这条效应被 M 挡住；
3. `(9,4011)` 上 **A=207 → B=208**：M=1 时**只改 N** 就把值搬到了 M=4 才有的那个值
   ⇒ 这是"两因素不独立"最直观的一处（它们作用到**同一个坐标的同一个值**上）。

**raw 与 scaled 的口径（本轮的规定）**：
* 六格之间的比较（A..F 内部）：`raw` 与 `scaled` **同一套** q/k 与同一条表达式，
  所以 `raw` 有差异 ⇒ 边界在 **`matmul`**；若 `raw` 相同而 `scaled` 不同 ⇒ 边界在**标量除法**。
  **本轮的实例：`raw` 已经不同** ⇒ 边界在 **`matmul`**，与 `√head_dim` 这一步无关。
* 与**保存张量**（`real_S`/`real_B`）的比较：生产把除法写在同一条语句里，**`raw` 从未被单独物化**，
  所以那里只有 `scaled` 是可比口径 ⇒ **门只取 `scaled`**；`raw` 的那两行（98508/394176 个坐标不同、
  比值恰为 `√128`）是**口径差异的记录**，**不是**分歧证据。这一条写进了 JSON 的 `raw_comparison_note`。

2. 观测对象 `A_vs_D`：第 0 行 **3 个坐标**不同、`max|Δ|=64`（raw）/`4`（scaled）。
3. `A_vs_C`（只改 M）与 `A_vs_D` **坐标集合/个数/幅值完全相同** ⇒ M 单独可完整复现观测差异。
4. `C_vs_D` 与 `E_vs_F` **逐位相同** ⇒ 在 M=4 下 N 的效应为 **0**（且不是内容造成的）。
5. `A_vs_B` 有 2 个坐标不同 ⇒ N 在 M=1 下**有**效应 ⇒ M/N **不独立**；
   且 M 效应的**坐标集合**随 N 变化（双向交互）。
6. `C_vs_E`、`D_vs_F` 逐位相同 ⇒ 第 0 行不受其余 query 行内容影响 ⇒ M 效应是**形状**效应。
7. `raw` 口径已不同 ⇒ 边界在 **`matmul`**（不是 `√head_dim` 除法）。
8. 15 项控制全部通过；两个 CUDA run 的六格 sha16 全部相同；与上一轮 `.pt` 第 0 行逐位相同。

**支持性推断（由上面的数支持，但不是本轮新测到的机制）**
* 由于两侧的 Q/K **数值**、`dtype`、精度开关、GQA 规则都相同，唯一差别是**执行形状**
  ⇒ 该差异与**执行形状相关**（shape-sensitive），这与"执行路径（kernel/tile/归约顺序）相关的数值差异"一致；
  **不**需要、也**不**允许升级为"实现缺陷"。
* 首跑（CPU）里 M/N 零效应 ⇒ 该敏感性应当是 **CUDA 后端**的性质，而非这组数字的数学性质。
* M=4 时对 N 与对"其余行内容"都不敏感 ⇒ 与"M=4 走了另一条（对这两者不敏感的）执行路径"一致。

**未证实（本轮没有测、也不声称）**
1. 具体是**哪个 kernel / 哪种 tile / 哪种归约顺序**造成 M=1 与 M=4 的差异（**本轮不做 profiler、不切后端**）。
2. 谁是数学真值（**未**做 FP32）。
3. N 在其它 M 下、M 在其它 N 下是否普遍如此（**只测了这一组**）。
4. 该模式是否在其它位置/长度/层/模型出现（**不外推**）。
5. 与上一轮 `q_proj`、`qk_matmul_scale` 的差异是否同源。
6. 六格各自"是否等于某个参考实现（如 FP32 或 HF）"——本轮**没有**做外部对照。
