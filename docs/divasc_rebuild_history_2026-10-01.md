## 2. 最小实现：每一步的原理 / 输入输出 / 缓存长度变化

**新增** `specdec/engine/spec_history_rebuild.py`（默认关闭）＋生产入口一个默认关闭的开关
`SMOKE_SPEC_REBUILD=1`（另有 `SMOKE_REBUILD_CAP_LEN`，默认 = `SMOKE_DIVCAP_POS-2` = 8237）。

| 步骤 | 原理 | 输入 → 输出 | 缓存长度变化 |
| --- | --- | --- | --- |
| 生产函数不动 | 只临时替换模块属性 `spec_dec.spec_decode_greedy`，`finally` 里 `restore()` 并用 `is` 核查 | 模块属性 → 诊断包装（**与生产同签名**，含 `k/eos_id/target_kv/draft_kv/log` 关键字） | — |
| ① 轮前快照 | `_verify` 会**就地改写**传入缓存（`cache["k"]=torch.cat(...)`）⇒ 必须在它**之前**克隆 | 活缓存 → 深拷贝 `H_pre`（deepcopy，保留全部层内键） | `H_pre`：pre |
| ② 原逻辑照跑 | 草案提案、块验证、接受/拒绝**完全沿用**（`m`、`emitted` 用原始值，**不**强制 AR token） | 活缓存 → `rows`、`g`、`m`、`emitted` | 块后 `pre+kp`（原逻辑） |
| ③ 逐 token 重放 | 从 **`H_pre` 的独立克隆**开始，把 `emitted` 依次喂入 `target`（显式 `_run`，阶段=decode，自做有限性检查；不经过 `smoke_hooks` 以免污染其覆盖账目） | `H_pre` + `emitted` → 重放缓存 + 末行 logits | pre → **pre+len(emitted)**（逐 token 一次） |
| ④ 替换 + 更新 | 用重放缓存替换下一轮 target 缓存；`saved_next` = **最后一次重放**的 logits | — | 下一轮 `pre' = pre + len(emitted)` |
| ⑤ 断言 | `cache_length == pre+len(emitted)`、`spec_cache.check_consistent`、逐层长度一致、`H_pre` 仍为 pre | — | — |
| ⑥ draft 不动 | 草案继续原更新规则（`trim_cache` + `_step`），**不**用 target 缓存替换、不改提案逻辑 | — | 草案与 target 逻辑长度按原契约一致（工具的不变量检查 `all_ok=True`） |

**明确不做的四件事**（本轮要求）：不在含接受 token 的 `pre+m` 缓存上重复追加；
不用旧块 logits 配新串行缓存（`saved_next` 一定取自最后一次重放）；
不给 Spec 注入外部 AR 缓存；不把重建后的数值冒充原始块验证值（逐轮字段 `orig_*` 与 `replay_*` 分开）。

**捕获（只读）**：重放中长度到达 `capture_len`（8237）时深拷贝快照；到达 `capture_row_at`（8239）时留档该行与喂入 token；
另有 `block_round`（若某轮**恰好**包含"预测 8239"的决策槽，则留档那轮的**真实块 rows/g/cands**，供四格工具当参考）。

## 6. 已证实 / 未证实 / 失败原因

**已证实（本轮）**
1. 串行重建**忠实执行**：64 次重放 = 64 个提交 token（逐 token 只追加一次）、长度契约逐轮成立且逐层一致、
   `H_pre` 未被改写、prefill 摘要与原 Spec 控制 **56/56 相同**（logits sha 相同）、不变量全过、无融合调用、
   两个包装 `restore` 的 `is` 核查通过 ⇒ **早期分叉不是记账/包装缺陷**。
2. **"块内 KV 历史 vs 串行重放历史"的差别是决策相关的**：第 6 轮位置 8208 的行从 323（拒绝 659）翻成 659（接受），
   从而改变整条轨迹（首分歧 8209）。
3. **该干预并没有让 Spec 变成 AR**：与 AR、与原 Spec 都在 index 17 分叉，而不是在 8239 汇合。
4. 同内容（AR vs 原 Spec）历史对照：**最早数值分叉 = 位置 8192、28/28 层、prefill 段逐位相同**（复现上一轮结论）。

**未证实（本轮无法回答）**
1. **A**：重建历史在**相同逻辑前缀**下是否与 AR 逐位一致 —— 前置条件（前缀到 8238 不变）失败。
2. **B**：原位置 8239 的判断是否由"历史差异"决定 —— 本轮两种口径都在已分叉的历史上，**不能**回答。
   （上一轮**同前缀**四格已给出该位置的历史效应：AR 历史 → 6702，原 Spec 历史 → 6652；本轮**没有**加强它。）
3. 本轮 8209 的翻转到底由**历史替换**还是由 **`saved_next` 来源改变**（块行→串行行）引起 —— 两者同时被改动，**未分离**。

**失败原因（为什么这一版设计答不了 A/B）**
* 逐轮重建把**两件事一起改**：① target 缓存历史的构造方式；② `saved_next` 的来源（块行 → 串行行）。
  两者都会影响下一轮 `g[0]`/`rows` 的判定 ⇒ 轨迹在第 6 轮就分叉，8237 之后的现场不再是"同一逻辑前缀"。
* 因此**不能**用"重建后历史仍与 AR 不同"去否定历史效应（那是内容差），
  也**不能**用"重建后仍是 3757/5534/279"去否定位置 8239 的历史效应（那是另一个上下文）。
* margin 不作为归因或豁免依据；即使 A/B/C 全通过也只是**本案例**诊断成功，不是 B6 通过或生产修复。
