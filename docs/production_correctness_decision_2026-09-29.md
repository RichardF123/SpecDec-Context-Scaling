# 生产正确性决策建议书

日期：2026-09-29  
资料基线：`5cc3ae3` 及之前已登记结果。  
状态：**建议稿，待小组批准；不是协议修订生效通知，不授权运行新实验。**

## 1. 建议结论

建议停止围绕同一分歧反复取证，转向评估“分层正确性与有限精度行为报告”路线。先批准其小规模证据收集方案，不直接批准生产验收或正式矩阵。

这一建议有实质代价：若生产 AR/SpecDec 仍不完全一致，研究必须明确承认这一事实，不能继续无条件声称对指定 BF16 AR 实现逐 token 无损。若课程或团队要求该承诺不可变，则不能走这条路线，应保留 exact-token 门，并接受部分条件受限或重新设计数值一致性路径的成本。

**当前不推荐**：把 QK FP32 默认化、继续叠精度开关、改 tie-breaking、仅小 margin 单步重算，或把 near-tie 标签直接当作生产 PASS。这些都没有解决已知历史缓存差异下的完整一致性问题。

## 3. 决策所依据的事实

1. 已有 CPU FP32 B6：10 case×两档=20/20。不是旧 B6 没跑全；缺的是最终生产配置和独立输入上的更广覆盖。
2. 8K、64-token 控制组可重复得到生产 AR/Spec 差异；两档共同前缀为31。
3. target QK FP32 将共同前缀延长至52/58，但仍不完整一致，并改变了 AR 自己的参考输出。
4. base/index52 的两条单步真实行被各自精确重放；只换历史缓存即可改变 argmax。尚未定位缓存差异的首发算子，未证明缓存被损坏。
5. finite 汇总契约 v2 修复了 required-but-missing 漏检；CPU 37/37 已复核。它是测试工具修复，不是生产 exact-token 已修复。
6. cuDNN prefill 的临时显存收益和局部可运行性有证据；最终多 family 性能稳定性、完整质量与生产验收没有由此自动成立。

## 4. 两条路线与研究代价

### 路线 A：保持指定生产 AR 的严格 exact-token 要求

**保留的保证**：所有进入有效主结果的 Spec 条件满足预登记的生产 token 一致性要求，参照明确且固定。

**需要做的工作**：审查是否能让当前验证和持久缓存更新遵守一个共同数值路径。只更改当前行不能保证历史一致；必要时可能涉及 canonical 缓存更新、重算或其他结构改变。这里列的是设计方向，不是现成实现或保证。

**最小验证**：选一个候选设计，先解释其状态不变量和数值合同，再检查两个已知反例及独立短/长 case。凡有额外重算，均计入时间与资源。不能把全串行 target 验证包装成已保留投机加速潜力。

**停止条件**：仍不能满足声明的合同、资源超限、工程预算超出预先额度，或实测代价使该路线不值得继续。停止后保留受限条件，不事后放松原判据。

**局限**：有限样本全等不是所有输入上的证明；性能可能为负。这条路线的研发成本目前未知，不作工时或成功保证。

### 路线 B：分层正确性与有限精度行为报告（推荐先评估）

**保留的硬要求**：算法结构、缓存与索引语义、因果性、检查覆盖、finite、有效生成长度以及同配置重复性。已有 FP32 B6 证据保留；代码或语义变更后需回归。

**不再隐含承诺**：生产 BF16 轨迹与某条 AR 数值实现处处完全一致。对未达到 exact 的条件，明确报告共同前缀、分歧比例和限制，不改写旧 exact CHECK/FAIL。

**新增证据负担**：独立输入上的行为差异范围、同前缀预测分布差异、最终配置的质量变化、完整运行稳定性。NLL 很接近不能单独证明生成语义等价，也不能将近贴边分类等同于无损证明。

**声明边界**：可研究所实现两种有限精度解码路径的资源与延迟；若输出不同，不得称为“完全相同输出下的无损加速”。吞吐需固定生成长度与停止策略并记录实际数目；不同轨迹可能改变接受率及工作量，必须视为解释限制。

**停止条件**：结构或有限性失败、质量/行为证据未达到事先批准的范围、重复性异常，或该范围无法与课程承诺相容。此时不放行，不通过扩大阈值来过门。

## 5. 为什么推荐先评估 B，而不是立即采用 B

项目目标是上下文、KV 表示与解码方式的实证，不是制造一个所有计算形状均 bitwise 相同的数值库。已有证据表明继续局部升精度不保证满足 exact 门，因此有必要评估更适合研究目标的分层验收。

但已有研究方向不自动允许取消原承诺。路线 B 会改变可声明的结论，尤其是 lossless 与等价工作的表述。它必须先经过小组确认；若课程对输出等价有硬性要求，还应与教师确认。不能因为它较省事，就把它当成已经合法生效。

推荐动作是：**批准研究路线与证据收集计划，不是批准验收阈值或放行正式实验。**

## 6. 若批准评估 B：最小、分阶段的证据方案

### 阶段 0：不运行 GPU 的预登记

- 从现有 manifest 选2个未参与此次诊断调参的8K families，例如自然文本与代码；确认来源、token hash及使用历史，避免把旧失败 prompt 改名当独立样本。
- 候选配置保持 cuDNN prefill、BF16 compute、k=4、chunk2048；不默认启用诊断 QK FP32。
- 两档 target KV，draft 保持 base_bf16；AR 为 target-only。不得只在8K换 backend 后把上下文效应与后端效应混合而不披露；后续正式矩阵应统一获准策略。
- max_new=64、EOS政策与输入固定；若正式实验选择更长输出，该最小测试不替代对应长度回归。
- 不改变模型、算法、默认配置或生产门禁。本文件只是指定待批准的实验候选，不直接配置运行器。
- 预先写出数据覆盖、有限性、相同配置重复性、异常退出和留证规则。

### 阶段 1：独立行为与重复性 smoke

2 families×2 KV×2 modes×2独立重复=16次运行；每次独立进程、串行，沿用环境/内存护栏。

记录完整token IDs、停止原因、首差位置、共同前缀、结构不变量、所有决策输入的finite、同配置两次重复是否相同、allocated/reserved和驱动占用。正确性诊断可插桩，但其时间不用于性能声明。

本阶段目标是检查已知现象能否在独立输入上被稳定描述；不是证明无损，也不是估计总体分歧率。出现OOM/崩溃/必需检查缺失/NaN或结构错误立即停止，不能只挑成功样本。

同配置重复输出不同则标记待查并停止推进。AR/Spec之间不同本身按路线B作记录，但尚无质量/行为准入决策，不能自动标“可生产使用”。

### 阶段 2：最终候选配置的独立质量证据

至少32个固定、不重叠的WikiText-2窗口，确认不与此前调参/诊断窗口重叠；有效评分token及移位严格一致。先在2K建立与既有质量协议兼容的基本评估；它不证明8K无损，8K还需独立长上下文评分设计及资源审查。

分开回答三件事：

1. **后端变化**：未量化KV下 eager 与候选融合后端的预测质量差。
2. **KV变化**：同一候选后端内 base_bf16 与 v_fp8 的质量差。
3. **解码数值路径**：在相同外部给定前缀上比较AR样式与块验证样式的对应决策行，单独定义cache构建合同、有限性与评分位置。

第3项是teacher-forced数值诊断，不是完整自由生成SpecDec的质量证明；标准AR PPL不能直接当作SpecDec生成质量。在需要声明任务质量保持时，还需相应独立任务评估，不能用PPL代替。

NLL按有效token聚合，报告paired窗口差和不确定性；PPL由汇总NLL指数化。若作区间估计，以窗口或family为重采样单位，不能把强相关token当独立样本。

### 阶段 3：验收决策及后续测量

**当前没有批准任何新的数值容差。** 小组需在阶段2独立验证运行前，决定是否采用非劣性要求、容差的研究依据、行为差异可接受范围和对应声明。不得从本轮已见差异反推一个刚好通过的阈值。

如果无法为容差给出合理依据，可以把质量差及区间作为描述性结果，但不能称“非劣/无损”。路线B下是否允许进入描述性性能研究，也需单独批准并明确不同输出工作量的限制。

验收通过后才冻结最终配置，进行4-family Pilot、测量稳定性检查，再决定正式≥16-family×12条件矩阵。所有新同步、重算或fallback成本进入最终计时。负加速可以保留为结果。

## 7. 对 near-tie 分类建议的处置

现有 `classify_bf16_compare` 的 `own_max_abs` 文档定义为同位置block-vs-serial差异。本次为不同缓存历史下single-vs-single，不应直接把0.25填入当作原定义的形状噪声。

若未来确需扩展分类器，先定义证据语义、参考重算方式和缺失处理。QK FP32不是全模型FP32；将已有BF16缓存转FP32也不是从共同前缀重算高精度历史。不能含糊标为“fp32真值”。

分类不是修复，且不是上述两路线的普遍共同前置。当前保留局部描述及待审状态即可，不因追求一个标签再启动昂贵实验。
