# RoPE 对齐后 AR/Spec 首个分歧（index 47 / 位置 8239）的定位（2026-10-01）

> **本轮只定位**：target 用 CPU-FP32 `inv_freq` 后，真实 AR/Spec 首个分歧（AR=6702 / Spec=6652，位置 8239）的成因。
> **未**启动正式实验；**未**改默认配置 / proposal / 正确性门槛；**未**新增精度开关或全模型 FP32 实验；
> **未**通过强制输出 AR token、放宽门槛或缩短生成长度制造 PASS。
> **B6 未过，本轮的定位**不构成**任何豁免**；正式正确性状态不变（未通过）。
> 前置：`563c53e`（对齐后 AR/Spec 仍不一致）、`docs/ar_spec_aligned_rope_2026-10-01.md`。

## 0. 结论（一句话 + 归因归属）

**决定因素是该分歧轮起点上 AR 与 Spec 的 target 缓存历史不同**（同执行方式换历史 → argmax 翻转）；
**同一历史下 single/block 的执行形状不改变该行 argmax**（两格都给出同一个 argmax）；
**未发现判断行/位置/mask/替换逻辑错误**（8 项数据流核对 + 泄漏检查全过）。
**执行形状通过"造出不同的缓存历史"间接起作用**——两臂历史**从位置 8192（第一个生成 token）起**在所有 28 层开始分叉，
而 **0..8191 的 prefill 缓存逐位相同**。

| 归因类别 | 判定 |
| --- | --- |
| ① 判断行/位置/mask/替换逻辑错误 | **已排除（本决策点）**：8/8 数据流核对通过（§3）、尾部泄漏检查通过且阳性对照成立、rollback 边界一致 |
| ② 同一历史下 single/block 形态差异 | **不是决定因素**：H_AR-S 与 H_AR-B 同为 6702；H_SP-S 与 H_SP-B 同为 6652（数值确有差异：max\|Δ\| 0.140625 / 0.203125） |
| ③ AR 与 Spec 既有缓存历史差异 | **是决定因素**：同执行方式下换历史即翻转（S：6702→6652；B：6702→6652）；两份历史在 8237 长度上 **55/56 张量逐位不同** |
| ④ 交互 | **存在且方向已定**：`执行形状 → 缓存历史 → 该行 argmax`（形状不直接决定该行） |
| 决定性机制（bf16 层面） | Spec 历史下 **6702 与 6652 都是 20.125（margin 0.0）**，argmax 并列取较小 id ⇒ 6652；AR 历史下 6702=20.125、6652=20.0（margin 0.125）⇒ 6702。**历史差异把 6652 的 logit 挪了 1 个 bf16 步长** |

⚠️ **margin 不作为豁免**：以上只是**机制说明**，不改变"严格一致性未达成"这一判定，也不放宽任何门槛。

## 3. 数据流核对：真实捕获值，不是重算值

**产物**：`divasc_20261001_cells_20261001T190925Z.json`（`CELLS_MODE=cpu_prov`，**纯 CPU、不加载模型**）。
**checks 全 True（8/8）**：

| # | 检查 | 结果 |
| --- | --- | --- |
| 1 | `rows[j]` 的 argmax ↔ **真实生成序列**在该行预测位置上的 token | `[389,6652,220,16]` ↔ 位置 8238/8239/8240/8241 的真实 token，**逐个一致** |
| 2 | `rows[j]` 的 argmax ↔ **当轮运行记录**的 `g[j+1]` | j=0,1,2 三处**一致** |
| 3 | AR 行 ↔ 位置 ↔ 输出 | 位置 8238 的行 argmax **6702** = 真实 AR 在 8239 的 token |
| 4 | 决策槽就是"预测 8239"的那一槽 | `slot2 source=rows[1] predicted_pos=8239 visible_last_key=8238` |
| 5 | rollback 边界 | `pre+m=8239`；`tgt_len_after=8240 = pre+m+1` ✔ |
| 6 | 替换规则 | `emitted == cands[:m]+[g[m]]`：**候选 5470 被拒**，改用 **6652** ✔ |
| 7 | 快照完整性 | 两臂 8237、28 层、键集合相同 ✔ |
| 8 | 两臂前缀 | 位置 8192..8238 的 47 个 token **逐 token 相同** ✔ |

**mask 泄漏检查**（`CELLS_LEAK_CHECK=1`，两臂各一次）：把**决策行之后**的尾槽 token 换成别的值后重跑，
**决策行逐位不变**（`decision_row_max_abs_vs_ref = 0.0`），且**阳性对照成立**（两个被替换的尾槽自身的行**确实改变**）。
⇒ 该行没有从 8239/8240 泄漏信息。

**因此的数据流解释（缓存 → 输入 → 判断行 → 拒绝/替换 → 输出）**：
`pre=8237` 的两臂各自缓存 → 4 个候选 `[5880,389,5470,220]` 一次性喂入 target（一个块）→
返回 4 行，每行预测 `pre+1+j`；**第 2 行（position 8238，可见 ≤8238）**给出 `g[2]=6652`，与候选 `5470` 不符 ⇒ `m=2`；
缓存 **trim 到 `pre+m=8239`**（保留块内算出的 KV），再用 `_step(target, 6652)` 追加修正 token ⇒ 输出 `[5880,389,6652]`。
位置、长度、掩码可见范围、rollback 边界**逐项一致**，**没有**错位或越界。

### 4.3 两份历史差到什么程度（逐张量 `torch.equal`，不是摘要）

`history_kv.elementwise`：**1/56 张量逐位相同**；唯一的那个是 **L0 的 K**（`n_diff=0`），

但"后续输出 token 相同"**不等于**"缓存状态相同"——本轮恰好证明了两臂 token 前缀相同而缓存不同。

## 5. 已证实 / 已排除 / 尚未证实

**已证实（本轮实测）**
1. 分歧现场可复现（序列与上一轮逐 token 相同；index 47 = AR 6702 / Spec 6652）。
2. 决策数据流与代码约定完全一致：`rows[j]` 预测 `pre+1+j`，决策槽 2 来自 `rows[1]`，可见 ≤8238；
   `g[0]=saved_next`（用真实生成序列交叉核对）；`m=2`、候选 5470 被拒、修正 6652；trim 到 8239、`tgt_len=8240`。
3. 无尾部 mask 泄漏（决策行在尾槽被替换后逐位不变，且阳性对照成立）。
4. 同一历史下，**s=1 与 s=4 在该行的 argmax 相同**（AR 6702/6702；Spec 6652/6652），但数值不同（max\|Δ\| 0.14–0.20）。
5. 同一形态下，**换历史即翻转 argmax**（s=1：6702→6652；s=4：6702→6652）。
6. 两份历史在 8237 长度上 55/56 张量逐位不同；**最早分叉在位置 8192、28/28 层**；prefill 段逐位相同。
7. bf16 层面：AR 历史 margin 0.125（6702 高一档）；Spec 历史 margin **0.0**（两者同为 20.125，argmax 并列取小 id）。

**已排除（在本决策点）**
1. 判断行来源错误（决策行不是别的行）；2. 位置错位（行 ↔ 位置 ↔ 输出 token 三向一致）；
3. 掩码泄漏/可见范围错误；4. rollback/截断边界错误；5. 接受/替换规则错误（`emitted=cands[:m]+[g[m]]`）；
6. 缓存快照不完整（不是只拷 K/V）；7. "该行由 s=1/s=4 直接决定"（四格反驳）。

**尚未证实（本轮无法判定，且**不**扩大扫描）**
1. **"逻辑错误" vs "可接受的数值敏感"** 的最终定性：本轮只证明**本决策点**没有可检出的逻辑错误，
   且翻转由历史差异驱动；**没有**做全流程记账审计（不扩大范围）。
2. **fp32 真实间隔未知**：现有 `classify_bf16_compare` 需要 `fp32_margin`，而它只能由 fp32 运行得到——
   本轮边界**禁止**精度实验 ⇒ 工具**未**调用该分类器、**未**给出任何 `BF16_NEAR_TIE` 判定。
   （这也是"不能用 margin 单独判定"的直接体现。）
3. **其他轮次/其他家族是否同因**：本轮只定位到 8239 这一个分歧点。
4. **B6 能否达成**：本轮不回答；改变历史一致性需要动 SpecDec 的缓存策略（见 §7），涉及与加速目标的取舍。

## 7. 唯一最小下一步（及验收条件）——**未执行**

> **一次"串行重建历史"的诊断对照**（1 组运行，仅诊断，**不改生产默认**）：
> 在诊断路径下，让 Spec 的**历史写入**与串行一致——每个 mismatch 轮在 `trim` 之后，把保留区间
> `pre..pre+m-1` 的 token **逐个单步重放**（块验证照旧保留），再继续下一轮；然后在同一现场重做：
> ① 两臂历史在 8237 处是否**逐位相同**；② 决策行 argmax 是否变为 **6702**；③ 完整 64-token AR/Spec 是否**逐 token 相同**。
>
> **为什么是它**：本轮把成因收敛到"**块内算出的 KV 被 trim 保留** ⇒ 两臂历史从位置 8192 起分叉"。
> 下一步要么**证实**这条因果（历史一致 ⇒ 分歧消失），要么**否证**它（说明还有第二个机制）。
> 这是唯一能把"定位"变成"可用结论"的最小实验，且不涉及精度开关、不改变门槛。
>
> **验收条件（二值）**：若 ①②③ 全为真 ⇒ 该分歧**完全**由块内 KV 的历史差异解释（随后才谈"是否值得为此付出
> 串行重放的性能代价"，这是独立的取舍问题）；若 ① 为真而 ② 为假 ⇒ 历史一致仍不足以一致，**另有机制**，
> 届时按"新证据"另行申报；若 ① 为假 ⇒ 我的干预没有忠实执行，**先查干预**、不向后归因。
>
> **边界**：1 组运行；不跑重复组/F06/正式矩阵/FP8/性能；**不**用 margin 当豁免；**不**改门槛；
> 历史产物绝不覆盖；**需单独授权**（本轮边界明确"只定位、不启动正式实验"）。
