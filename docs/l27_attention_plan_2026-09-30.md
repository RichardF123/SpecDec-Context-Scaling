## 4. 最小实验条件表（**唯一**的有界实验；本轮不执行）

**设计原则**：控制点选在 **RoPE 后、attention 核心之前**；K/V 直接用已落盘的 `cache.pt`（不重新生成）；
所有比较的**有效可见范围固定为 `key ≤ 8216`**；先复用生产路径，功能式复现必须先过重放门。

### 4.0 补采阶段 vs 局部重放阶段（**资源必须分开记账**）

**阶段 A（补采，一次性 GPU 重放）**：要拿到 L27 的**完整四行 RoPE 后 Q**，必须让 L27 真正被调用一次，
而 L27 的输入来自**前面 27 层**——因此补采**不是「单层操作」**：它需要
① 把 `round11_snap_pre`（28 层 × `(1,2,8215,128)` bf16 ≈ **236 MB**）搬到 GPU；
② 用候选 4 个 token 跑一次**完整 28 层 forward**（与生产 verify 同路径）；
③ 在 L27 上只读捕获目标张量。
**峰值显存 ≈ 模型 2.87 GiB + 全 cache 236 MB + 激活（4 token）**，与既有诊断运行同级，**不是**单层 8.4 MB。
单层 K/V 的 8.4 MB **只是第 ③ 步要记录/校验的对象大小**，**不能**当作补采成本。

**阶段 B（局部重放，纯张量运算）**：只用阶段 A 捕获的 `q/k_all/v_all` 做功能式复现与 G1/G2 对照，
**不再调用模型、不再跑 forward**，显存需求 = 单层 `(1,2,8219,128)` 量级（**< 20 MB**）。

| # | 补采对象（阶段 A） | 形状 | 大小（bf16） |
| --- | --- | --- | --- |
| 1 | L27 **RoPE 后 `q`**（完整 4 行） | `(1,12,4,128)` | 12,288 B |
| 2 | L27 **实际参与本次 attention 的 K/V**（`k_all`/`v_all`，RoPE 后、**GQA 之前**） | `(1,2,8219,128)` ×2 | 8.4 MB（与既有 `blk` cache 同对象，**校验后不重复落盘**） |
| 3 | L27 **attention 核心输出**（AV 后、`o_proj` 前） | `(1,4,1536)` | 12,288 B |
| 4 | L27 `o_proj` 输出（**生产重放校验专用**） | `(1,4,1536)` | 12,288 B |
| 5 | L27 输入 `input_layernorm` 输出 | `(1,4,1536)` | 12,288 B |
| 6 | 对齐行 1 的 **scores / 概率**（**只存对齐行**，不存全矩阵） | `(1,12,1,8219)` ×2 fp32 | 394 KB ×2 |
| 7 | mask `(4,8219)` bool + 位置/T/可见范围元数据 + RoPE 表参数摘要 | JSON | < 10 KB |

**合计新增落盘 < 1 MB**（另加既有 8.4 MB 的校验引用）。**不保存**逐层、逐行的 attention 矩阵。

| **G0b** | **功能式重放门**（必须先过） | 与 G0a 完全相同的 Q/K/V/形状/mask/缩放，用提取的函数式核心（`scores → mask → softmax(fp32) → 回转 bf16 → AV`） | **无**（重放） | 功能式**四行**核心输出必须**逐元素等于** G0a 捕获的核心输出。**不得**先用单行 Q 去要求它复现块输出 |
| **G1** | **只改查询行数** | 同一份 Q 的对齐行、**同一 K/V**（T=**8219**）、同 dtype、同缩放、**有效范围同为 keys 0..8216** | **只改查询行数**：4 行 → 1 行；单查询取 `q[:, :, 1:2, :]`（保持 `(1,12,1,128)` 与 head 布局） | 单查询**显式使用与块行 1 逐元素相同**的 mask（`(1,8219)`，True 位置 == 块行 1）；**不得**走生产 `s==1` 的「不施加 mask」捷径（那会看见未来 key）；同一份 Q 的其它行**保持原样、不另行生成** |
| **G2** | **只改被屏蔽的 K/V 长度** | G1 的单查询 Q 与调用形状、缩放、dtype、**有效可见范围 keys 0..8216** | **只改 T**：8219 → 8217 | 前 8217 个 K/V 必须与被截断前**逐元素相同**（纯切片）；T=8217 时 mask 为全可见（可见 8217 个 = 0..8216），与 G1 的**有效范围一致**；分别记录物理长度、mask 布局、实际有效范围 |
| **G4'** | **核心 vs `o_proj` 分离** | 各条件的对齐**核心输出统一 reshape 成 `(1,1,1536)`** 后，调用**同一个** `o_proj` | 无额外变量 | 报告 `o_proj` 时必须是**统一单行形状**的结果；**块形状的 `o_proj` 只用于生产重放校验**并**单独标注**，**不得**让 `o_proj` 形状随条件变化后把最终差异全归因核心 |

**变量纪律**：G1（行数）与 G2（长度）**分开**；**任何一组都不允许「行数与长度同时变」后再称为纯形状效应**；
本轮**不更换 Q/K/V 数值来源**、**不混入 AR 历史 cache**。

★ **对齐行可见范围（本次修订的明确值）**：对齐位置 **8216**，可见 keys **0..8216，共 8217 个**。
块行 `i` 可见 `key ≤ 8215+i` ⇒ 行 1 可见 `≤8216` ✓；位置 8217/8218 对该行**不可见**。

### 4.2 每组结果支持什么 / 仍不能证明什么

| 结果 | 支持 | 仍不能证明 |
| --- | --- | --- |
| **G0a/G0b 任一不通过** | ——（**停止**，落盘原因，**不进入归因实验**） | 任何 attention 归因 |
| **G1 对齐行输出逐元素相等** | 在本例**固定输入**下**未观察到**「查询行数（4 vs 1）」这一变量的效应 | **不**代表所有输入或所有 kernel 都正常；不说明差异从何而来 |
| **G1 对齐行输出不同** | 该**受控变量**在本例**产生了数值差异** | **不**自动等于 bug；**不**证明它导致 576/4710 翻转 |
| **G2 对齐行输出逐元素相等** | 在本例固定输入下**未观察到**「被 mask 的未来 K/V 长度（T=8219 vs 8217）」的效应 ⇒ mask 与 kernel 行为符合预期 | 不说明 K/V **数值来源**是否等价（G3 暂缓） |
| **G2 对齐行输出不同** | 「物理长度」在本例是**真实存在的数值变量** | 不说明 8217 的选词为何翻转；也不是 bug 判定 |
| **G4' 统一单行 `o_proj` 后仍有差异** | 差异**在核心输出里就已存在**（未被 `o_proj` 形状污染） | 不能说明差异来自 attention 的哪一步（QK / softmax / AV） |
| **G4' 统一单行后差异为 0** | 差异**只在 `o_proj` 的形状上**，不在核心 | 不能说明核心无关（本条件只测到 o_proj 边界） |

**统一立场（解释边界）**：
- 输出**相同** ⇒ 只能说「**本次固定输入下未观察到该变量效应**」，**不能**推广到其它输入或 kernel；
- 输出**不同** ⇒ 只能说「该**受控变量**在本例产生数值差异」，**不**等于 bug，**不**证明导致 576/4710 翻转；
- **不**宣称解释了原始 **AR=715** 的历史贡献（本轮不碰 AR cache）；
- **不**作性能声明、**不**放宽门槛、**不**标正式 correctness 通过。

## 5. 重放校验、资源估计、停止条件

### 5.1 预先声明的断言（任一失败 ⇒ **立即停止**，写 `checks_failed` 并保留记录）

1. 对齐位置：`snap_pre` 长度 == **8215**；块 4 行位置 == 8215..8218；**对齐行 == 行 1**（输入位置 8216，预测 8217）；
   **对齐行可见 keys == 0..8216，共 8217 个**；块行 `i` 可见 `key ≤ 8215+i`；
2. Q 布局：**`q` 为 `[batch, query_heads, query_len, head_dim]` = `(1,12,s,128)`**（按 `model_self.py:351` 的
   `view(b,s,12,128).transpose(1,2)` 核验）；K/V 为 `(1,2,T,128)`（GQA 扩展**前**）；
3. 前缀：Spec cache 长度 == **8215**；共同前缀位置区间 == **0..8214**；已生成 token 前 25 个相同；
4. **mask 语义**：`scores` 只在**有效位置**检查有限性；**被 mask 位置必须恰为 `-inf`**，
   这**不是**「非有限失败」，而是预期值 —— 检查要分开写，**不得**把 `-inf` 误报为非有限；
5. shape 断言**先行**，禁止广播比较；`(1,12,1,128)` 与 `(1,12,4,128)`、`(1,1,1536)` 与 `(1,1536)` 等一律显式断言；
6. **独立快照**：读入的 cache 必须 **deep clone**（生产 `SelfAttention.forward` 会**原地改长** `cache["k"]/["v"]`）；
   运行前对源张量做快照，运行后逐元素校验**源快照未被覆盖**、**历史 cache 未被误写**；
7. **全张量 finite**：对参与比较的完整张量实算 `isfinite`（概率、核心输出、Q/K/V），**不抽样、不只看首元素**；
8. **裁剪正确性**（G2）：截断后的前 8217 个 K/V 必须与截断前**逐元素相同**，且**有效可见范围仍是 0..8216**。

### 5.2 资源与护栏

- **串行执行**（一次一组条件）；**不改** 16 GiB commit 护栏；**不**提高任何内存上限；
- 显存：只加载 1.5B bf16（≈2.87 GiB）+ 单层 cache 片段（L27 一个长度 8219 的 K/V ≈ 8.4 MB）；**不需要** 8K 全 cache 上 GPU；
- 落盘：补采 < 0.5 MB + JSON 摘要 < 50 KB；**不**保存逐层大型 attention 矩阵；
- **无**自动重试、**无**精度干预、**无**参数搜索、**无**全层扫描；
- 不新增性能测量；诊断时延一律**不进入**任何加速比表格。

### 5.3 停止条件（**已删除「明显超过 1–2 ULP 就停止」这类模糊规则**）

1. **G0a 或 G0b 重放门不通过** ⇒ 落盘原因并**停止**，**不进入归因实验**；
2. 任一**必需断言失败** ⇒ 停止（含：位置/mask/快照/裁剪/有限性/shape）；
3. **环境拒绝、OOM、出现非预期非有限数** ⇒ 保存原因并停止；
4. 若**必须改生产代码**才能构造条件 ⇒ 停止并**先**提交方案（本方案不要求任何生产改动）；
5. **完成 G0/G1/G2 后即停止**，**无论结果相同还是不同**（不做「因为不等所以再追加」的自动延伸）；
6. **不自动重试、不换参数、不提精度、不追加实验、不倒查逐层**；
7. **不**新增任何数值阈值或豁免；**不**因结果回溯修改既有结论或放宽正式门槛；
8. G3（K/V 来源）**本轮不执行**：AR cache 与同历史串行 cache **不可混用**，需另行设计。

## 6. 与既有 0.0625 的口径澄清（本轮同时修正文档）

存在**两个数值都等于 0.0625、但来源完全不同**的量，报告中必须分开书写：

| 编号 | 来源 | 固定什么 | 变什么 | 数值 |
| --- | --- | --- | --- | --- |
| **(A) MLP 差异传播** | `mlptail` T_A vs T_B 的**最终 logits** | **LM head 与 Norm 的调用形状** | **MLP 的调用形状**（经残差与 Norm 传播） | max\|Δ\|=0.0625 |
| **(B) LM head 形状差异** | `tailshape` P1 vs P2、以及 `lmhead` A vs B | **隐藏向量**（同一个 T） | **LM head 的 M 维调用形状** | max\|Δ\|=0.0625 |

两者**不可互相引用**：(A) 是「输入差经 head 放大后的结果」，(B) 是「同一输入的 head 自身形状敏感度」。
并且两者都**没有**落在判决三坐标（576/715/4710）上（那里差为 0.0）。
