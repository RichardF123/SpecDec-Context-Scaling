# 位置 8209 的 LM head 边界定位：分歧来自**投影输入**（2026-10-02）

> **本轮只做一件事**：把位置 8209 的 S/B 判定差异定位到 **LM head 边界**上——
> 是**已经进入投影的输入**（最终 RMSNorm 输出 `hS` vs `hB`）造成的，还是**最终投影本身的执行形状**
> （`(1,1,H)@W.T` vs `(1,4,H)@W.T`）造成的。
> **不做**逐层定位、**不改**计算路径、**不做**全模型 FP32、**不做** FP32 投影、**不**自由生成、
> **不**扩 family/精度/算子扫描；生产实现/proposal/门槛一律未动；GPU 单进程串行；硬失败落盘停止（无自动重试）。
> **B6 未过 ⇒ 本轮的局部定位不构成任何豁免；正式正确性状态不变（未通过）。**

## 0. 结论摘要（**实测 / 支持性推断 / 未确定** 严格分开）

**实测（本 run 直接测到）**

6. 四格控制成立：`HS_1` 与真实 S 行、`HB_4` 与真实 B 行**逐元素相同**（差 0.0）

7. 两次 run（首跑因缺陷中断 + 完整 run）**五个格的行 sha16 完全相同** ⇒ 跨进程确定性。

**支持性推断（由上面的数支持，但不是本轮新测到的机制）**

* 位置 8209 的两个候选在 bf16 上是**贴边**的（`margin = 0.125` = 该量级 1 ULP；三格里干脆**精确并列**）。
  输入差异在这个尺度上足以把 323 从 23.75 推到 23.625；投影形状的 1 ULP 级扰动**不足以**越过它。
* **该差异是"执行形状"的纯数值后果，不是内容后果**：引擎分块验证的掩码是
  `mask = triu(ones(s,T), diagonal=p+1)`（`p=T-s`）⇒ 第 0 行（位置 8208）**被掩掉列 ≥ 8209**，
  数学上**看不到** 8209..8211 这三个候选；而 RMSNorm 与 MLP 都是**逐行**运算。
  ⇒ 位置 8208 的隐藏态**只**由 ≤8208 的 token 决定 ⇒ `hS ≠ hB` 只能来自
  **不同执行形状下的 bf16 舍入差**（跨 28 层的 GEMM/softmax/reduction 形状不同），
  **不是**"多喂了三个 token 的内容"造成的。
* 因此上一轮的结论链可以收窄：**块执行 vs 单步执行 ⇒ 隐藏态数值差（≤1.0，多数 1–2 ULP） ⇒
  在贴边处翻转判定**；在 LM head 这一层，投影本身**不是**驱动因素。

**未确定（本轮没有测、也不声称）**

* **323 / 659 谁是数学真值**：本轮**没有**做 FP32 投影/FP32 对照 ⇒ **不做** `BF16_NEAR_TIE` 类判定，
  也**不**把 0.125 / 0.0625 说成"数值误差应当消除"。
* **该差异在上游的哪一步产生**：`hS ≠ hB` 只说明"差异**已经进入** LM head 的输入"——
  **不能**据此认定最终 RMSNorm、某个注意力算子或某个投影有 bug。要判定必须**再向上游移动一个边界**（§10）。
* 本结论**只**覆盖"同一份 H、位置 8209、这 4 个候选"；**不**外推到别的位置/别的长度/别的历史。
* 本轮**没有**捕获"未加诊断的自由生成时那一行的完整 logits"⇒ 只能声称"复现了**已保存的局部对照行**"，
  **不能**声称与未捕获的原始自由生成整行一致。

## 1. 边界定义与固定配置（逐项核对）

**边界（代码事实，`lmhead_boundary.code_facts`）**

```
QwenLM._run:  ... 28 层 → x = self.norm(x)  → if need_logits: logits = x @ self.embed_tokens.weight.T
```
* **无独立 `lm_head`**：输出权重 = `embed_tokens.weight`（绑定权重），本 run 实测
  `shape=[151936,1536]`、`dtype=torch.bfloat16`、`n_params=233373696`、`is_embed_tokens_weight=True`。
* `RMSNORM.forward`：**fp32 内部** `mean(x²)` + `rsqrt` ⇒ `normed.to(orig_dtype)` ⇒ `weight * normed`
  ⇒ 输出回到 **bf16**（捕获实测 `dtype=torch.bfloat16`，与引擎一致）。
* 因此"捕获点"= `self.norm` 的输出，用 `register_forward_hook` **只读**记录（不改 `_run`、不改张量）。

**固定配置（与本轮四格/上一轮 run 逐项一致）**

| 项 | 值 |
| --- | --- |
| 协议 | F13、ctx=8192、chunk=2048、k=4、`base_bf16`（KV 未量化）、**all-eager** |
| 精度 | `qk_fp32=False`、`prob_fp32=False`；`allow_bf16_reduced_precision_reduction` 默认 True → 显式置 True（effective True，与 AR/Spec/重建 smoke 记录一致）；`allow_tf32=False` |
| RoPE | target 用已验证的 CPU-FP32 `inv_freq`（作用域还原 `ok=True`，`n_calls=4`，全部 `target\|cpu_fp32`） |
| draft | 本实验**不加载 draft**（只做 target 的单步/块与投影） |
| 权重 | `lowmem_load` 逐张量 `torch.equal` 338/338（`weights_bitmatch=True`） |
| 注意力计数 | `strategy=eager`、`fused_by_phase={}`、`decode=56 / verify=56`（= 28 层 × 2 次 S/B 前向，含关闭捕获的那一遍） |

## 6. 已证实 / 未证实 / 控制失败（**分开列**）

**已证实（本 run 实测）**
1. 边界事实：无独立 `lm_head`；边界 = 最终 RMSNorm 输出；`y @ W.T == logits`（逐位，CPU 门）。
2. 控制复现：S=323（并列）、B=659；与已保存局部对照行**逐元素相同**；与 argmax 锚点一致；关闭捕获逐位不变。
3. `hS ≠ hB`：1343/1536 坐标不同，`max|Δ|=1.0`，median 2 ULP（|x|≥1 子集）。
4. **更换输入 ⇒ 在两种投影形状下都翻转**（`source_effect_1row` / `_4row` 都是 323→659）。
5. **更换投影形状 ⇒ 两种输入下都不翻转**（形状效应只有 134/171 个坐标、≤1 ULP）。
6. 布局控制这个具体对照**无效**（两个"不同"形式的张量其实是同一个，见 §7②）——如实记录，不据此宣称"布局无影响"。

**未证实（本轮没有测）**
1. 323/659 谁是数学真值（**未**做 FP32；**不做** `BF16_NEAR_TIE` 判定）。
2. 该差异在上游的哪一步产生（LM head 输入之前）；**不**认定任何算子有 bug。
3. 位置 8239 与 8209 是否同源；结论**不**外推到别的位置/长度/历史。

**控制失败**：**无**。两个真实格都逐元素复现了捕获行；位置口径、克隆独立性、源/权重完整性、跨 run 确定性全部成立。
