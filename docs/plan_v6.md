## 1. 目标与定位（一句）

在 8GB 消费卡上从零实现 1.5B 推理引擎并逐级优化（L2 KV-cache / L4 权重量化 / L4b fp8 KV / L5 固定链投机解码），实测 {2K,4K,8K}×{fp16,fp8} 的接受率/净加速/ppl，并用 **M1 归因分析**回答"投机解码何时失效、为什么失效、fp8 KV 能否延长"——诚实实证定位，对照 EAGLE-2(2406.16858)/MagicDec(2408.11049)/QuantSpec(2502.10424)/KIVI(2402.02750)。

## 2. 方案架构总览（范围三层 + 工程模块 + 数据流 + 门）

### 2.1 范围三层（承诺纪律）

| 层 | 内容 | 承诺 |
|---|---|---|
| **A 层 · 保障** | 纯 PyTorch：L1→L2→L4(int8/int4)→L4b(fp8 KV)→L5(固定链,现成词表共享 draft)；{2K,4K,8K}×{fp16,fp8}×(接受率,净加速,ppl)=**18 格契约**；外部基线(transformers/gpt-fast 二选一)+复现+报告(含 3–5 页短文)+演示 | **只对 A 承诺**；零 CUDA 依赖；≈185–193h |
| **K · 受控承诺** | 单 CUDA kernel K1 = 融合 RMSNorm+SwiGLU(100–150 行)，三级降级链，G0 总开关 | 有门有盒有止损；不进 A 契约 |
| **B 层 · 加分** | 动态 draft 树(默认不开)、自训头(不开)、int4/int2 KV(不开)、gpt-fast(不开) | 仅在主线提前 ≥2 周时择一 |

### 2.2 工程模块架构

```
specdec/
├─ engine/     前向·attention·KV-cache·采样·decode 循环 (OURS)
├─ quant/      L4 int8/int4 (OURS)
├─ kv_quant/   L4b fp8 KV (OURS)
├─ kernels/    K1 CUDA 扩展 (OURS, 受控承诺; torch.utils.cpp_extension)
├─ spec_dec/   L5 draft+verify 循环 (OURS)
├─ bench/      A10 基准运行器 + 测量钩子 + M1 拆解/归因/盈亏平衡脚本
├─ cli/        specdec run --stage … / eval / repro
└─ docs/       results.jsonl(只追加)+ config 哈希 + 图
LIB(借并注明): HF 权重加载/tokenizer/lm-eval-harness 仅评测
```

### 2.3 运行时数据流（一次 A10 主基跑产出一切，不新增实验）

```
固定 prompt 集+seed → 投机解码跑批 {2K,4K,8K}×{fp16,fp8}×(投机开/关)
  → 测量钩子采集原始量(jsonl)：
     接受率α、proposed/accepted、每步 kv_read 耗时、每步 verify 耗时、
     draft 耗时、总 wall、生成 token 数、ppl
  → results.jsonl(哈希链) → M1 拆解：归因堆叠图 + 盈亏平衡表 + 18 格表
```

### 2.4 M1 测量钩子埋点（§4 开工清单即此）

decode 循环内 torch.cuda.Event 分段计时：draft / verify / kv_read / other；kv_read 在 fp16/fp8 两路径均埋。若 L3 走融合 kernel 致 kv_read 不可分离 → 用"attention 整段计时+理论带宽下限"近似并标注。

### 2.5 门体系与决策点

- **G0（9/14）**：CUDA 工具链冒烟总开关（最小扩展编译+trivial kernel 对齐 eager）。
- **G1（≈10/14）**：L1–L2 对齐主里程碑（greedy 输出 vs gpt-fast/transformers max|Δ|<1e-3）。**A7–A10 起始日 = G1 关闭 +0/+1 周**。
- **10/17 再评估点**：G1 未关 或 周容量连两周 >22h ⇒ 启用 §6 证据格分级并知会导师。
- **G2（11/10）**：B 层决策（是否已具备"主线提前 ≥2 周"条件）。
- **G3（11/14 冻结，神圣）**：冻结对象 = A 层 18 格核心数字组；K1 基准属独立加分数据，未完成可冻结后单跑、不进核心表。

## 4. M1 归因分析（协议精要）

- 三分量：净加速 S(L) = 草稿发散收益 G(α(L)) − KV 读取带宽成本 K(L) − 验证开销 V(L)。α=实测接受率；G 由 α 推"期望每验证接受 γ token → 前向节省 1/(1+γ)"；K 与 V 由钩子计时。
- **盈亏平衡上下文长度 L***：对 S(L) 三点（2K/4K/8K）做单调插值求 S=1.0 根；fp16 与 fp8 各一。
- 输出：归因堆叠图（fp16/fp8 各一）+ 盈亏平衡表 + 结论句模板"fp16 L*≈X，fp8 L*≈Y"。
- **关键约束：不新增实验**——原始量全部在 A10 同批采集；§4 开工清单交付当天即可执行。

## 5. 受控承诺 K1（CUDA，M2）

- 范围：融合 RMSNorm+SwiGLU（100–150 行）；**总开关 G0(9/14)**。
- **时间盒 ≤18h；窗口 10/20–10/31（量化轨并行期）；开关 = A6(L4) 绿且 A7(fp8) 未阻塞主线**（不再绑定"报告完成度"——消除 v6 内矛盾；报告条件移作 B 层通用开关）。
- 三级降级：① 集成进 decode 路径（eager 对齐 <1e-3）→ ② 独立 kernel-vs-eager 基准（不进核心表）→ ③ 放弃，systems 章节留档。
- **未达门叙事**：systems 章节 = 工具链研究+kernel 尝试+停下的实测原因；systems 维度从不缺席，只转化为证据。

## 6. 证据格分级（D3；A 层"永不空手"）

- 契约 18 格；**10/17 触发条件**：G1 未关 / 周容量连两周 >22h / 可用总工时 <40h 窗口。
- 分级：退为 **2K/4K 全档 + 8K fp16 单档（15/18）**；8K fp16-KV ↔ 8K int8-KV 互为等价格（fp8@8K 质量崩时以 int8 代）。
- 每次降格同步知会导师；降格 ≠ 降级到无证据。

|---|---|---|---|---|
