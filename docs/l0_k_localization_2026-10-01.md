# 第 0 层 K 差异的有界定位：复现门、节点对照与条件式 RoPE 表替换（2026-10-01）

> **本轮只回答一个问题**：既有两份 C1 快照里第 0 层 K 的 **60 个元素差异出现在哪个环节，RoPE 是否能解释它们？**
> **不**解释 AR/Spec 的最终 token 分歧，**不**改生产模型/协议/门槛/proposal，**不**跑完整生成、FP8、性能或正式矩阵。
> **B6 未过 ⇒ 仍禁止 acceptance 测量/pilot/final；正式正确性状态不变（未通过）。**
> 文档勘误：`docs/xb_clone_bug_errata_2026-10-01.md` §11（更正 §7/§8 的六条过度推断）。

**一句话结论（因果链，全部经复现门与逐元素核对）**：
自研 `Build_Rope_cache` 在 **GPU** 上算 `inv_freq = 1/(theta**e)`，HF 在 **CPU**（`RotaryEmbedding.__init__`）算同一式子
⇒ `inv_freq` 在下标 **18**（以及 50）处相差 **1 个 fp32 ULP** ⇒ cos/sin 表在**频率下标 18** 上出现 114+88 个 bf16 差异
⇒ 在**逐位相同**的 RoPE 前 K 上做旋转，正好产生**逐位相同于既有快照**的那 **60** 个 K 差异。
**旋转运算本身不是原因**（同一张表喂给两侧实现，输出逐位相同）。

## 3. 第 0 层前向依赖与数据流（读源码所得）

| 实现 | 第 0 层 K 的实际路径（**含中间节点**） | 出处 |
| --- | --- | --- |
| 自研 | `Embedding.weight[ids]` → `layers[0].input_layernorm`（`RMSNORM`：fp32 内部算、回 cast bf16，再乘 bf16 权重）→ `self_attn.k_proj`（`nn.Linear(1536→256, bias=True)`）→ `view(1,n,2,128).transpose(1,2)` → `Build_Rope_cache` → `apply_rope` | `model_self.py:12-17, 40-52, 59-60, 349-355, 469-473` |
| HF 5.16.1 | `model.embed_tokens(ids)` → `layers[0].input_layernorm`（`Qwen2RMSNorm`）→ `self_attn.k_proj` → `view(1,n,-1,128).transpose(1,2)` → `model.rotary_emb(x, position_ids)` → `apply_rotary_pos_emb`（`(k*cos)+(rotate_half(k)*sin)`） | `modeling_qwen2.py:280, 189-191, 203-211, 384-385, 89-102, 113-135` |

**只跑这些模块**即可得到 L0 的 K/V：**不**需要第 1–27 层、**不**需要 attention、**不**需要 LM head、**不**需要生成。

所以按 chunk 重放与原始整段运行在第 0 层 K/V 上等价——这一点**不是靠推理**，而是由 §5 的复现门实测确认。

## 4. 最小重放设计（每个实现一次，原 chunk 形状）

* 每个 chunk 按**原始 2048 行**计算：`ids = seq[st:en]`、`position_ids = arange(st, en)`（与 C1 的 `[0,2048)/[2048,4096)/[4096,6144)/[6144,8192)` 完全一致）；
  **不**抽单点、**不**缩小矩阵形状；所有比较与抽取都在**计算完成之后**做。
* 节点保存：`embed`、`norm`、`k_pre`(RoPE 前 K)、`v`、`cos`、`sin`、`k_post`(RoPE 后 K)，以及 `ids`/`positions`；
  每个节点记录 `dtype/shape/stride/numel/有限性/min/max/sha16`。
* 保持既有运行条件：bf16 权重（自研侧 `lowmem_bf16_build`，**338/338 逐张量位级一致**）、
  `allow_bf16_reduced_precision_reduction=True`、QK32/PROB32 关闭、`chunk=2048`、原投影调用形状；
  两侧**顺序执行**（各自独立进程，绝不同时驻留）。
* 形状/步长实测：`k_pre` 两侧都是 `(1,2,2048,128)`、`stride=(524288,128,256,1)`（transpose 后的非连续布局，两侧**相同**）；
  `ids`/`positions` 两侧**逐位相同**（`ids_sha` 831e129f… / 9fa4ca36… / 691493b7… / 6ee890da…）。
* 表布局差异（**不是数值差异**）：自研 `cos/sin` 为 `(1,1,seq,dim)`，HF 为 `(1,seq,dim)`；比较时按广播**语义对位**后进行。

* **input RMSNorm 输出完全相同** ⇒ `RMSNorm` 环节（fp32 内部、cast、乘权重）**不是**差异来源
  ——这一条是**实测**，不是"按顺序推理排除"（勘误之二 §11.2 第 1 条）；
* **RoPE 前 K 逐位相同**（4 个 chunk、共 2,097,152 个元素全等）⇒ `k_proj` 投影环节**不是**差异来源；
  这一条同时**否掉**了"`k_proj`/`v_proj` 可能选到不同 kernel"的顾虑（勘误之二 §11.2 第 2 条）；
* **第一个已检查且不同的节点 = `k_post`**，且在它之前唯一未检查的输入就是 **cos/sin 本身**：表**确实不同**
  （共 6+24+42+42=114 个 cos、8+14+28+38=88 个 sin 表项不同）；
* 每 chunk 的 `k_post` 不同元素数 **4 / 9 / 21 / 26**，与 §2.2 快照差异的分块分布**完全一致**（合计 60）。

⇒ 按规则进入 §7 的**条件式 RoPE 替换对照**（`rope_substitution_allowed=true`）。

## 8. 表构造诊断：为什么表会不同（根因，**无模型、无前向**）

工具 `L0_MODE=table`。产物 `l0_replay_table_20261001T144149Z.json`。参数取自真实 config：`theta=1e6`、
`head_dim=128`（两侧一致才继续）。

| 检查 | 结果 |
| --- | --- |
| `inv_freq` = **GPU** 上算（自研 `Build_Rope_cache` 的实际做法） vs **CPU** 上算（HF `__init__` 的做法） | **逐位不同**，差异下标 = **[18] 与 [50]**（64 个中 2 个） |
| 下标 18 | GPU `0.020535249263048172` vs CPU `0.020535251125693321`；\|Δ\|=1.86e-09；**fp32 位模式差 −1**；相对 9.07e-08 |
| 下标 50 | GPU `2.05352516786661e-05` vs CPU `2.0535249859676696e-05`；**位模式差 +1**；相对 8.86e-08 |
| `matmul`(HF 写法) vs `torch.outer`(自研写法)，**同一份 inv_freq** | **逐位相同** ⇒ 运算写法**不是**原因 |
| HF 链（CPU inv_freq + GPU matmul） vs 自研链（GPU inv_freq + outer）的 `freqs` | 逐位不同，差异下标 18 与 50 |
| 由两条链重建的 **bf16 cos/sin 表**（全 8192 位置） | cos 不同 **114** 个、sin 不同 **88** 个，**按频率下标 = {18: 114} / {18: 88}** |
| 重建表 vs **既有 dump 里实际使用的表**（4 个 chunk，cos+sin） | **全部逐位相同**（8/8 项 True） |

* 追加核对（CPU）：HF 侧记录下来的 `inv_freq` 的 sha16 = `138c99b109d7affb`，**等于 CPU 算出的那一份**，
  而 GPU 算出的那一份是 `d0260aaaaed04542` ⇒ HF 的表确实来自 **CPU 计算**的 `inv_freq`（与其源码一致）。
* 下标 50 虽然 fp32 也差 1 ULP，但在 0…8191 这 8192 个位置上**没有**造成任何 bf16 表项翻转（实测 cos/sin 差异只在 18）。

**因果链（已验证的局部因果）**：

```
inv_freq 的算法设备不同（自研 GPU / HF CPU） → inv_freq[18] 差 1 fp32 ULP
  → freqs[:, 18] 差 ~1e-7 相对 → cos/sin 表在频率下标 18 上 114+88 个 bf16 表项不同
  → 在逐位相同的 RoPE 前 K 上旋转 → 60 个 L0 K 元素不同（= 既有快照的 60 个，值也逐位相同）
```

**纪律**：① "有差异 ≠ 实现错误"——两侧都是 1-ULP 级的 `pow`/除法舍入差别，**不**据此断言哪一方"更对"；
② 本轮**没有**改动任何生产代码；③ 本轮**没有**证明表对齐后 C1 会一致（见 §0 未知项）。
