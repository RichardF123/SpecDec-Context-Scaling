## 1. 为什么需要新判据（**旧判据失败的原因已被定位，而且原因不在新分支**）

§9 的逐项干预给出三条硬证据：

1. **旧判据的两个界在不同输出尺度上朝相反方向失效。**
   算子级 12 行里，`T=8192` 的行 `abs` 只有 1.5e-3（远小于 1e-2）却 **失 `rel`**（1.24e-2）；
   而 `s=T=2/2048` 的行 `rel` 合格（4.3e-3/7.9e-3）却 **失 `abs`**（1.56e-2/2.34e-2）。
   ⇒ 一条"绝对 ≤1e-2 **且** 相对 ≤1e-2"的判据，在 bf16 注意力上**不可能同时满足所有输出尺度**
   （注意力输出的量级随可用 key 数变化约 50 倍）。这是判据本身的性质。

2. **差异的主导来源是 eager 基线自己。**
   eager 在 softmax **之前**把 QK 分数舍入成 bf16（`model_self.py` 的 `matmul` 输入是 bf16）。
   真实张量上逐项干预：**只有 R1（分数舍入）有实质贡献**，去掉它整模型 logits 差**缩小 12–13×**
   （17.91→1.35 / 17.34→1.43），逐层把唯一的巨差点（第 0 层）**缩小 186–194×**；
   融合侧在尖峰区**比 eager 侧更接近 fp32**。

3. **残差不可归因，且排序不稳定。**
   即使把 R1、R2 都去掉，融合路径与 fp32 参考之间仍有 0.8–1.7（logits）的地板；
   在已去掉 R1 的基础上再去掉 R2，两种 kv 下方向**相反**（base 变差、v_fp8 变好）
   ⇒ 该残差处在"融合路径 vs fp32 近似参考"的**不一致噪声量级**。

**结论**：旧判据实际在问"两条**精度不同**的实现能否逐位一致"，答案是"不能"；
而它**没有**问项目真正关心的问题。**这不是放宽标准的理由，而是判据选错了对象的证据。**

## 2. 项目真正关心什么（判据应当对准的量）

按阶段报告 §9.8 的五类**必须分开**：

| 类别 | 应当判据化的量 | 现状 |
| --- | --- | --- |
| 算子误差 | 融合路径是否**不劣于**基线（而不是"等于"基线） | 已有 fp32 受控参考可判 |
| 生成差异 | 后端切换是否**改变行为** —— 量化 + **声明**，而不是要求为零 | 已量化（argmax 一致率、生成 id 是否同） |
| 质量损失 | NLL/PPL 是否**不劣化**（要有规模） | 已有诊断规模口径（需扩规模才可正式声明） |
| 内存收益 | 8K 峰值是否**落进硬件**（D1 的原始动机） | 算子级成立，端到端**未测** |
| 性能收益 | 本阶段**不测** | 无有效计时 |

## 3. 三个候选方案（含取舍，**请选一个或提出第四个**）

### 方案 A（**推荐**）：把判据从"等价"改成"**不劣 + 行为改变已声明**"

| # | 判据 | 说明 |
| --- | --- | --- |
| A1 | 数值：以 **fp32 受控参考**为基准，要求 `\|fused − fp32\| ≤ 1.5 × \|eager − fp32\|` | 问"融合侧是否更差"，不再问"是否逐位相同"。当前数据显示融合侧**更准**，故该判据可通过且**有信息量** |
| A2 | 行为：**必须**记录并**声明** argmax 一致率与生成 id 是否相同 | **不作通过条件**。后端切换允许改变行为，但必须可见、可追责 |
| A3 | 质量：在与现有 2K 口径**同规模**的评测上 `NLL(fused) ≤ NLL(eager) + 0.05` | 0.05 参照：诊断规模下实测 +0.035，**HF 自身 eager↔sdpa 差 +0.043** ⇒ 阈值取"不低于同类后端切换的自然量级" |
| A4 | 内存：8K `peak_reserved ≤ 8188 MiB` | 硬件线，是 D1 的真正目标 |
| A5 | 阶段分流：`fused_by_phase` 只含 `prefill`；非 prefill 的 fused 计数恒 0；短块回退**可数**；`assert_strategy_used()` 通过 | 已验证项，直接沿用 |

**理由**：对准项目真正要用的东西；**不再把基线自身的精度缺陷记到新分支账上**。
**风险**：明显弱于"逐位一致"；**不能**用来支持任何"两条路径等价"的表述。

### 方案 B：保留旧判据，但**先把基线也修成 fp32 分数**

把 eager 的 QK 分数改为 fp32（即把现有 `DIAG_QK_FP32=True` 变成**默认**），提高基线精度后再要求一致。
- **优点**：一致性判据重新变得有意义；顺带修掉一个**真实的精度缺陷**（R1）。
- **缺点**：**改动了冻结基线** ⇒ 与历史 G1–G5 全部数据**不可比**，需重跑基线；
  成本最高，且违反本项目"不同时改动多个量"的纪律。
- **注意**：若采纳 B，`DIAG_*` 开关的定位要从"仅诊断"升级为"正式实现"，需单独评审。

### 方案 C：不设等价判据，改为**双报告**

每次同时报告 eager 与 fused 两套结果 + 差异 + 质量，不设通过/不通过。
- **优点**：零门槛、零争议；最适合"把后端**当作自变量**来研究"的场景。
- **缺点**：无法据此做"是否可替换"的判断；且当前 RQ1–RQ3 **不包含后端因子**，
  直接采纳会把后端变成混杂项而不是研究变量。

## 4. 与 **D1**（是否批准 CUDNN attention amendment）的关系

| 若采纳 | D1 的推进方式 | 代价 |
| --- | --- | --- |
| **A** | 在"**质量不劣化** + **8K 内存达标**"两个条件下推进；**但**任何 8K eager↔融合对比都必须**显式声明后端混淆** | 低（~1 次 smoke + 一次同规模质量评测） |
| B | 先改基线 + 重跑历史口径，再谈替换 | 高（数小时 + 历史数据断层） |
| C | D1 变成"把后端作为实验因子"，与现有 RQ 设计冲突，需改 RQ | 中（改实验设计，需重新登记） |

## 5. 我的建议

**建议采纳 A**，并同时明确一条**限制条款**：
> 本分支**不承诺**与 eager 逐位等价；任何"等价/可互换"表述都**不被**本阶段的证据支持。

**在确认之前**：旧判据与旧结果**原样保留**；本文件不改变 `results_schema.py` 的任何 gate，
也不改变任何已落盘的结果。

# 附：8K smoke 的**预登记**解释规则（**跑之前写死**）

配套工具 `specdec/engine/g5_8k_smoke_cudnn.py`，运行器 `scripts/run_g5_attn_forensics.cmd smoke [MIN_COMMIT]`，
配置 `ctx=8192 / chunk=2048 / k=4 / max_new=16 / base_bf16 / arm=cudnn_prefill`（**冻结，不改**）。

## P1 成功（"能跑"）的定义
- `stage=complete`；
- 两模型 logits 全有限；生成 id 长度正确且**全部在词表范围内**；
- 权重逐位校验通过（target 338 + draft 290）；
- `assert_strategy_used()` 为 `ok`；
- 内存时间线含 `before_load / after_load / after_decode` 三个时点，且
  **PyTorch 记账与设备侧 `nvidia-smi` 占用分开记录**。

## P2 判定线（**预登记，跑完不改**）
| 观测 | 记法 |
| --- | --- |
| 8K `peak_reserved ≤ 8188 MiB` | **内存达标** |
| 8K `peak_reserved > 8188 MiB` | **内存未达标**（**即使跑通**也照此记） |
| OOM / 原生崩溃 / 被护栏拒绝 | **未达标**，落盘后**停止** |

## P3 解释纪律（不得违反）
1. **首次跑通只代表"能跑"**，**不构成**稳定性结论（无重复）；
2. **不构成**速度结论：计时字段含插桩，**禁止**进入任何 speedup 表；
3. `allocated` **不是**全部物理显存占用；`reserved` 超过显存**不单独**作为分页证据；
   ⇒ 必须同时给出设备侧占用与当时的其它 GPU 消费者数量；
4. 失败时**不重试放大**、不改 `chunk/k/dtype`、不启动正式矩阵；
5. 与历史的可比性：与台账 §4.17.x / §4.19 的 8K `peak_reserved`（eager 下 10.48–10.72 GiB）
   **同类可比**，但**必须注明**本次为 `lowmem_load` 双模型加载路径。

## P4 已经量到的"前置基数"（排练，`ctx=512`，**不是** 8K 结论）
| 时点 | pt_allocated | pt_peak_reserved | cuda_free | smi_used |
| --- | --- | --- | --- | --- |
| after_load（双模型驻留） | 3906.6 MiB | **4134.0 MiB** | **2947.0 MiB** | 4859.0 MiB |
| after_decode | 3906.6 MiB | 4874.0 MiB | 2191.0 MiB | 5615.0 MiB |

⇒ 双模型驻留留下约 **2947 MiB** 余量；`ctx=512` 的工作集只多约 740 MiB。
**8K 的工作集（KV 增长 + 末块 logits + 激活）尚未测量**，因此"能否跑通"仍属**未测试**。
